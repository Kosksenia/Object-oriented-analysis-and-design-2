# Лабораторная работа №4

## Паттерн «Стратегия» (Strategy): Система эволюции покемонов

### Предметная область

Паттерн **«Стратегия» (Strategy)** широко применяется в разработке игр и приложений, где требуется выбирать алгоритм поведения во время выполнения программы. Один из примеров — система эволюции покемонов.

**Система эволюции покемонов** — это компонент приложения, который отвечает за хранение информации о покемонах, их стадиях развития и правилах эволюции. В зависимости от вида покемона и его состояния, эволюция может происходить по разным правилам (достижение уровня, использование камня, обмен, высокая дружба и т.д.).

### Описание проблемы

В мире покемонов существует множество различных способов эволюции:

- **Эволюция по уровню** — покемон эволюционирует при достижении определённого уровня;
- **Эволюция с использованием камня** — для эволюции нужен определённый камень (Водный, Огненный, Гром-камень и т.д.);
- **Эволюция при обмене** — покемон эволюционирует только при обмене между игроками;
- **Эволюция по дружбе** — эволюция происходит при достижении максимального уровня дружбы в определённое время суток;
- **Эволюция с предметом** — для эволюции нужен определённый предмет, который покемон должен держать.

Если клиентский код (например, игровой движок) будет содержать всю эту логику в виде условных операторов, возникнут проблемы:

1. **Громоздкий код** — метод эволюции превратится в длинную цепочку `if-else` или `switch` с проверкой всех возможных условий;
2. **Сложность добавления новых типов эволюции** — при добавлении нового правила придётся изменять существующий код, что нарушает принцип Open/Closed;
3. **Дублирование кода** — одинаковые условия могут повторяться для разных покемонов;
4. **Сложность тестирования** — невозможно протестировать каждое правило эволюции изолированно;
5. **Нарушение Single Responsibility** — класс покемона будет отвечать за слишком много разных типов эволюции.

### Решение проблемы

Использование **паттерна «Стратегия» (Strategy)** для реализации системы эволюции покемонов.

Паттерн гарантирует, что:

1. **Единый интерфейс** — все стратегии эволюции реализуют общий интерфейс `EvolutionStrategy`;
2. **Изолированные алгоритмы** — каждая стратегия инкапсулирует своё правило эволюции в отдельном классе;
3. **Взаимозаменяемость стратегий** — стратегию можно легко заменить во время выполнения;
4. **Добавление нового типа эволюции** не требует изменения существующего кода — достаточно создать новый класс, реализующий интерфейс `EvolutionStrategy`;
5. Клиентский код не зависит от конкретных алгоритмов эволюции.

## Ключевые особенности реализации

### Динамический выбор стратегии эволюции

В версии с паттерном система позволяет динамически назначать стратегию эволюции для каждого покемона:

1. **Создание покемона с выбранной стратегией:**
   - Создаётся объект покемона с указанием его имени и начального уровня;
   - Выбирается подходящая стратегия эволюции (LevelEvolution, StoneEvolution, TradeEvolution, FriendshipEvolution);
   - Стратегия привязывается к объекту покемона полиморфно через интерфейс.

2. **Проверка возможности эволюции:**
   - Вызывается метод `canEvolve()`, который делегирует проверку стратегии;
   - Стратегия проверяет своё специфическое условие (уровень, камень, предмет).

3. **Выполнение эволюции:**
   - Вызывается метод `evolve()`, который также делегируется стратегии;
   - Стратегия возвращает новую форму покемона (следующую стадию).

### Иерархия стратегий эволюции

| Стратегия | Условие эволюции |
|-----------|------------------|
| LevelEvolution | Покемон достиг определённого уровня |
| StoneEvolution | У игрока есть соответствующий камень |
| TradeEvolution | Покемон был обменян |
| FriendshipEvolution | Дружба >= 220 и время суток подходящее |


## Преимущества реализации

1. **Расширяемость** — новые типы эволюции добавляются без изменения существующего кода
2. **Инкапсуляция** — каждое правило эволюции изолировано в своём классе
3. **Полиморфизм** — все стратегии работают через единый интерфейс `IEvolutionStrategy`
4. **Гибкость** — стратегию можно изменить во время выполнения (например, при получении камня)
5. **Тестируемость** — каждую стратегию можно тестировать отдельно от контекста
6. **Переиспользование** — одна стратегия может использоваться разными покемонами

## Вывод

Паттерн «Стратегия» позволил создать гибкую, расширяемую систему эволюции покемонов, в которой все правила эволюции инкапсулированы в отдельные классы. Это наглядно демонстрирует преимущества паттерна:

- **Слабая связанность** между покемоном и правилами эволюции
- **Возможность динамической замены** алгоритма поведения
- **Изолированность** каждого правила эволюции
- **Возможность добавления новых типов эволюции** без изменения существующего кода
- **Единообразная работа** с любыми стратегиями через общий интерфейс
